## What was done
- New `app/prompt_store.py`, class `PromptStore` (also `get_store()` / `reset_store_for_tests()`; nothing calls them yet).
  - Reading: `list_prompts`, `get_prompt` (blocks in template order, locked ones read-only with the shipped text and `locked: True`),
    `active_id`, `history`, `status`, `warnings`, `validate` (live guard check), `preview` (final text and estimated tokens, no network).
  - Writing: `save(prompt_id, changes, base_version, note)`, `save_as_new`, `restore`, `reset_block`, `reset_prompt`, `delete`,
    `set_active`, `resolve_conflict("mine" | "theirs")`. `changes` is `{block id: {text, enabled, title, order} | None}`; None removes a custom block.
  - Sync: `refresh`, `apply_snapshot(prompts, active)` (the entry point the 5D listener will use), `flush`, `seed`, `sync` (refresh, flush, seed).
  - `build(role)` / `text(role)`: memory only, memoised until a block, the active choice or a placeholder value changes.
  - Order of winners per block: Firebase block if valid, else the last good copy in `prompts_cache.json`, else the shipped text.
    The guard runs when a block is read from Firebase or the cache, on save, again before upload, and again at use.
  - Self-check at use: `wire_problems`; on failure the shipped default for the role is used and a warning is kept.
  - Guard rules: no literal trigger phrase; for `task_extraction` no `DUPLICATE_DETECTED` and no output label lines; 4000 characters per
    block, 20000 in total; no saved API key text (plus two key shapes, `gsk_...` and `AIza...`, in case the key was typed on another device);
    unknown `{TOKEN}`s and a prompt over 6000 characters are warnings only. Locked block ids and ids the template does not have are
    ignored on read with a warning.
  - A save is a conditional write (version check inside a Firebase transaction), then a history entry `ksm/config_versions/prompts/<id>/<n>`, then pruning to `PROMPT_VERSIONS_KEEP`.
  - Offline, switch off or no Firebase: the save becomes the working copy at once and waits in the `pending` part of `prompts_cache.json`
    (not in the Phase 4 outbox, because that outbox only does plain writes and a prompt save is a conditional one). A pending save whose prompt
    changed online is not uploaded; the store reports state `conflict` until `resolve_conflict`.
- `app/cloud_sync.py` (additions only): `TransactionAbort`, `SERVER_TIME`, `transaction(path, fn)` on `MemoryCloud` and `FirebaseCloudStore`,
  and a new fake `MemoryTreeCloud` (a real nested tree, nulls and empty objects dropped, server clock filled in, `online` switch).
  Existing behaviour is unchanged.
- Decisions to know about: several offline saves of one prompt upload as ONE version; "Reset block" and "Reset prompt" write the shipped text
  (so the console still shows it) instead of deleting nodes, and each is a version; `seed` creates a built-in prompt at version 0, adds only
  missing blocks, and raises `template_version`; `updated_at` is the server clock; `SYNC_PROMPTS` and `PROMPT_VERSIONS_KEEP` are read from the
  settings store directly (`config.reload()` is unchanged); the online copy is authoritative, so a prompt that disappears online is dropped here
  with a warning.
