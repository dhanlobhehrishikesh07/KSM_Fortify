## What was done
- New `app/shared_settings.py`, class `SharedSettings` (also `shareable_keys()`, `get_shared()`, `reset_shared_for_tests()`; nothing calls them yet).
  - Paths: COMMON `ksm/config/settings/<KEY>`, PER-DEVICE `ksm/config/devices/<deviceId>/settings/<KEY>`; each node `{value, updated_at (server clock), updated_by}`. The 18 shareable keys come from the scopes (secret kinds excluded again); `_where()` gives no path to a LOCAL ONLY or SECRET key.
  - `seed()`: per key, a transaction that writes only if the node is missing (never overwrites); skips a key whose edit waits and any key an environment variable overrides; uses the saved value, then old `.env`, then the default.
  - `refresh()` / `apply_snapshot(settings, devices)` (the entry point the 5D listener will use): applies valid COMMON values and valid PER-DEVICE values of THIS device through `store.set` (so the store's listeners, and with them `config.reload()`, run); Firebase wins when it differs (the store's `.bak` and history keep the old value); keys outside the right scope or place, other devices' nodes, bad shapes, invalid or key-like values are ignored with a warning (no value in the warning). Returns `applied`, `restart` (DATA_FILE_NAME, DEBUG_UI), `conflicts`, `warnings`.
  - Local edits: a store listener (`attach()`) queues the key (`pending`: last value, FIRST base `updated_at`) in `shared_settings_state.json` (config folder) and starts a background thread to send, so an edit never waits for the network. A key set by an environment variable is never queued. Deleting a saved value sends the default. With the switch off or no Firebase: nothing queued, no cloud call.
  - `flush()`: per key a transaction that aborts when the node's `updated_at` is not the base; on abort the other value wins, is applied, a NOTICE `{key, mine, theirs, at_ms}` is kept (`notices()`, `dismiss_notices()`, saved in the state file, text passed through `redact_text`). Stops at the first cloud failure; the rest stays queued.
  - Never uploaded, never accepted: any value containing a saved key or the shape of one (`gsk_...`, `AIza...`, same test as the prompt guard), a value over 2000 characters, a value that fails `validate_value`.
  - `register()` writes `name`, `kind`, `last_seen` under `ksm/config/devices/<id>`; `sync()` = refresh, register, flush, seed, refresh again if anything was seeded; `status()` states: off, no_firebase, starting, synced, pending, offline. Turning `SYNC_SETTINGS` on asks for a background `sync()`.
- `app/settings_store.py` (addition only): `SettingsStore.value_ignoring_env(key)` returns `(value, source)` as if no environment variable existed; secrets return `("", "secret")`. No existing behaviour changed.
- Decisions to know about: (1) a key an environment variable overrides is skipped by edit AND seed, not uploaded under its saved value; (2) seed uploads the effective local value including defaults, so a first device fills the console with all 18 keys and a second device's own differing saved values then lose to Firebase (backup kept); (3) a setting deleted in the console is re-seeded from the local value at the next sync; (4) a send that fails is retried only at the next `sync()`, `flush()`, edit or app start (no timer; 5D may add one); (5) if Firebase holds an unusable value for a key with a waiting edit, the edit is sent over it on the following flush.
