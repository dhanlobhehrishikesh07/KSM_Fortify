## What was asked
Add `get_sync_status`, `sync_now` and `export_cloud_data` to `WebAPI` (methods only, no UI), per ROADMAP 4F-1.

## What was done
- `web_api.py`: new optional `task_sync` argument (stored private as `_task_sync`). Three new public methods:
  - `get_sync_status()`: returns `{ok, state, label, pending, last_sync, last_error, kinds}`. State is `off` (no switch on), `offline`, `pending` or `synced`. Pending counts only the kinds whose switch is on, each by its own outbox paths (tasks, chats, audits+scans). Label is "Off", "Synced", "Offline", "Pending N". Error text is redacted. Never raises.
  - `sync_now()`: asks each switched-on sync to send in the background and returns the status plus `started` (a list of kinds). With all switches off it sends nothing and says so in `message`.
  - `export_cloud_data()`: reads tasks, chats, audits and scans from the cloud, removes keys, writes `exports/ksm-cloud-export-<time>.json` in the config folder (atomic, owner-only mode, never overwrites), returns `{ok, path, counts}` or `{ok: False, error}`. Download only; works with all switches off.
- `cloud_sync.py`: `SyncEngine.export_all()` (all-or-nothing read; never raises).
- `chat_sync.py`, `record_sync.py`: small `sync_now()` (kick if switch on), same as `TaskSync` already had.
- `main_window.py`: passes `task_sync=online[0]` to `WebAPI`.
- No UI change. No change to the task data file.
