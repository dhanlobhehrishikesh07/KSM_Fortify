Do 5E from ROADMAP Phase 5: `WebAPI.prompt_*` and settings methods (methods only), the PROMPTS tab (locked blocks grey with a lock and read-only; editable blocks with text box, switch, "reset block"; add own block; live guard check; preview with estimated tokens; Save, Save as new, history with Restore, Reset, Delete, Set in use), and the SETTINGS badges, this device's values, the theme and the new switches.

## What was done
- `app/gui/web_api.py`: new methods only (no public attribute): `prompts_get`, `prompt_get`, `prompt_validate`, `prompt_preview`, `prompt_save`, `prompt_save_as_new`, `prompt_restore`, `prompt_history`, `prompt_reset_block`, `prompt_reset`, `prompt_delete`, `prompt_set_active`, `prompt_resolve_conflict`, `prompt_new_block_id`, `config_status`, `config_dismiss_notices`, `get_theme`. All return a plain dict, never raise (a failure becomes `{ok: False, message}`), and pass message text through `_redact`. The constructor takes optional `prompts`, `shared`, `hub` (kept private as `_prompts_obj`, `_shared_obj`, `_hub_obj`; default: the process-wide instances, looked up at call time). `settings_get` now also returns a `shared` block (`config_status()`).
- `app/settings_store.py`: `SYNC_PROMPTS`, `SYNC_SETTINGS`, `PROMPT_VERSIONS_KEEP` are no longer hidden (shown in the SETTINGS tab). `THEME` stays hidden: the theme buttons set it.
- `app/gui/webui/index.html`, `app.js`, `style.css`: new PROMPTS tab (role buttons, prompt list with IN USE / BUILT-IN / EDITED / WAITING / CHANGED ELSEWHERE badges, status line and warnings from `prompt_use.notes()`, block editor, live guard check 300 ms after typing which disables Save on errors, Preview, History with two-step Restore, two-step Reset prompt and Delete, Set in use, Save as new with a name box, Add your own block, Keep mine / Take theirs on a conflict). All calls go through `callApi`, which never throws or rejects. Text from the backend is always set as text. SETTINGS: a scope badge on every row (COMMON, THIS DEVICE, LOCAL ONLY, SECRET), "SET BY ENVIRONMENT", a SHARED SETTINGS box (state, this device's name and id, edits that lost with Dismiss). Theme: a click applies it and saves it through `settings_set("THEME")`; at start `get_theme` applies this device's saved theme without writing it back.
- `app/gui/webui/style.css`: slate theme `--text2` darkened from #6b7280 to #626976 (it was 4.23:1 on the second panel colour, the item left open in 4F-5; now 4.84:1), found by the new contrast test.
- `tests/test_prompts_api.py`: new, 25 tests. `tests/ui/ui_smoke.test.js`: fake prompt API and 23 new tests.
- `tests/test_config_scopes.py`: one test changed on purpose: `test_new_settings_are_hidden_from_the_settings_tab_until_their_steps_are_built` became `test_new_settings_are_shown_since_5E_except_the_theme` (hidden set is now `{"THEME"}`; the three others must be shown). Every other assertion unchanged.
- Decisions to know about: (1) no header chip for the shared configuration; status shows on the PROMPTS tab and in the SHARED SETTINGS box; (2) PROMPTS status refreshes every 3 s only while the tab is open; (3) "this device's values" are shown as the THIS DEVICE badge plus the device name and id line, not as a separate list; (4) a block text longer than 4000 characters is refused by the backend guard (the counter turns red).
