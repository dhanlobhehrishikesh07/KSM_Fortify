## What was asked
Start the build: sub-session 5A of ROADMAP Phase 5. Split the shipped prompts into locked and editable blocks without changing
the assembled words, move the audit prompt out of the code, give every setting a scope, add the new settings and the device
id file, and extend the Firebase rules for `ksm/config` and `ksm/config_versions`.

## What was done
- New `app/prompt_templates.py`: the four role templates (ordered blocks, locked or editable, one insert point), the parser for
  the block files, `assemble()` (overrides, switched-off blocks, extras at the insert point, tight joins), `fill()` for the four
  placeholders, `wire_problems()` (trigger phrase for chat; `DUPLICATE_DETECTED` and the five parser labels for extraction).
  `TASK_TRIGGER_PHRASE` is now defined here once; `app/ai_assistant.py` re-exports it.
- The three prompt files now use block markers (`@@@ block <id> <editable|locked> [tight]`, `@@@ insert`); the audit prompt moved
  out of `strategy_officer.py` into the new `prompts/strategy_audit.txt`. The file must match the code's layout or it is refused.
  Locked: chat `trigger_rule`, `confirmation`; extraction `input_context`, `dedup_reply`, `categorization`, `output_format`;
  audit `data_description`. Screen scan has none. Editable shipped text writes `{TRIGGER_PHRASE}` instead of the phrase.
- `ai_assistant`, `strategy_officer` and `screen_analyzer` now read their default prompt through `prompt_templates` (no Firebase,
  no overrides yet). `render_prompt` also fills `{TRIGGER_PHRASE}`. A damaged or missing file behaves as before: empty prompt
  (chat, extraction), the built-in fallback (screen scan), a clear `StrategyOfficerError` (audit).
- `settings_store.py`: `scope` on every `SettingDef` (common 11, per-device 7, local-only 4, secret 2, as in the plan); `hidden`
  flag (hidden settings are validated and stored but not listed by `describe()`); four new hidden settings `SYNC_PROMPTS` (true),
  `SYNC_SETTINGS` (true), `PROMPT_VERSIONS_KEEP` (30, 5 to 200), `THEME` (scifi, saffron, slate, forest); `keys_with_scope()`;
  `device_identity()` (makes `device.json` once: id `d-` plus 8 hex digits, name defaults to the computer's name); choice
  validation now returns the canonical spelling and ignores case (needed for the lower-case theme ids; LOG_LEVEL unchanged).
- `config.py`: `STRATEGY_AUDIT_PROMPT_FILE`.
- `firebase/database.rules.json`: new `ksm/config` (settings, devices with per-device settings, prompts with blocks,
  prompt_active, and `$other` false) and `ksm/config_versions`. The key lists, the locked block ids and the roles were generated
  from the code. All existing rules are unchanged (compared as parsed JSON).
