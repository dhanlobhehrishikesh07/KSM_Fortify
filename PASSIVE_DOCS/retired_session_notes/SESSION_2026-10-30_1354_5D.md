## What was done
- `app/cloud_sync.py` (addition only): `TreeMirror` (rebuilds a subtree from the SDK's put/patch/null events), `ListenHandle` (`close()`), `FirebaseCloudStore.listen(path, on_tree)` (one SDK listener; `on_tree` gets the whole subtree after every event; errors become `CloudError`; a consumer that raises never kills the connection), `MemoryTreeCloud.listen` (first snapshot at once, then after every write at, above or below the path; offline raises `CloudError`). `_notify` is called after `set`, `delete` and a committed `transaction`.
- `app/prompt_use.py` (new): `built(role)`, `text(role)`, `notes(role)`. The one door for the AI modules to `PromptStore.build`. Memory only. `PromptTemplateError` (shipped file unusable) passes through so each caller keeps its old behaviour; any other failure of the library is logged and the shipped text is used. When `SYNC_PROMPTS` is on and Firebase is configured but the text in use is not the online one (cache, shipped, or the self-check fell back), a plain warning is added to `Built.warnings`, kept in `notes()` and logged once per change.
- `app/config_sync.py` (new): `ConfigSync` hub. `start()` returns at once (attaches `SharedSettings`, watches the settings for `SYNC_PROMPTS`, `SYNC_SETTINGS`, `ENABLE_FIREBASE`, `FIREBASE_DATABASE_URL`, `FIREBASE_SERVICE_ACCOUNT_PATH`, then runs `reconcile()` in a background thread). `reconcile()`: both layers off or no Firebase = no connection, no read, no write (an open connection is closed); otherwise opens ONE listener on `ksm/config` (never twice) and runs `PromptStore.sync()` and `SharedSettings.sync()`. Each event tree goes to a worker thread (a burst is merged into the newest tree) and then to `PromptStore.apply_snapshot(prompts, prompt_active)` and `SharedSettings.apply_snapshot(settings, devices)`, each only while its own switch is on; a part that did not change (for example another device's `last_seen`) is not applied again; `config.reload()` runs after a setting was applied. A failed connection or sync is retried with a growing pause (30 s, doubling to 300 s; `retry_s=None` turns it off). Also `status()`, `stop()`, `get_hub()`, `start_config_sync()` (never raises), `reset_hub_for_tests()`.
- `app/ai_assistant.py`: chat and extraction use `prompt_use.text(role)` (new `_prompt`); `_shipped_prompt` and `render_prompt` kept. `app/strategy_officer.py`: audit text from `prompt_use.text("audit")`. `app/screen_analyzer.py`: `load_prompt` from `prompt_use.text("screen_scan")`, fallback prompt kept.
- `app/gui/main_window.py`: `start_config_sync()` is called before the assistants are created and `stop()` in the `finally`. No file under `webui` or `web_api.py` was changed.
- `tests/conftest.py`: an autouse fixture resets the prompt library, shared settings, hub and `prompt_use` before and after every test (they are process-wide instances now).
- `tests/test_prompt_templates.py`: one existing test (`test_screen_scan_prompt_comes_from_the_blocks_and_falls_back`) now resets the prompt library after it patches a prompt file, because the library keeps its built text and a shipped file never changes in a running app. No assertion was changed.
- Decisions to know about: (1) `config.reload(shared.store)` is called by the hub itself after settings were applied or a watched setting changed, so it does not depend on `WebAPI`'s own listener; (2) a hub that is off for both layers still watches the settings, so turning a switch on later opens the connection without a restart; (3) the first sync of a computer runs after the listener opens, so the first snapshot is applied before seeding; (4) `status()` of the hub (listening, events, last error, both layers' status) and `prompt_use.notes()` are ready for 5E; nothing shows them yet.
